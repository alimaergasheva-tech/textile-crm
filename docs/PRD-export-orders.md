# PRD — Модуль «Экспортный заказ» (расширение textile-crm, фабрика Export Product)

## 1. Цель
Автоматизировать полный цикл экспортного заказа готовой продукции (пример: коллекция SET44, клиент STREET LIGHT, бренд VTEME, 10 моделей, 3 500 шт/модель, отгрузка в США): от лида с запросом цены и сроков до финального отчёта AQL 2.5 и отгрузки.

## 2. Пользователи и роли
| Роль | Задачи |
|---|---|
| Менеджер продаж | лиды, КП, связь с клиентом, отправка образцов |
| Технолог | табели мер, BOM, расход полотна и фурнитуры, раскладки |
| Закупщик | заказы Узтекс (полотно) и Eren Textile (фурнитура) |
| Планировщик | Gantt, мощности цехов |
| Образцовый цех | 1-fit и PP образцы |
| ОТК / инспектор | входной контроль, AQL 2.5, фотоотчёт |
| Логистика | отгрузка в США |
| Клиент (отдельный аккаунт, уже есть в textile-crm) | просмотр КП, статусов, подтверждение образцов, отчёта AQL |
| Директор | себестоимость, маржа, риски по срокам |

## 3. Бизнес-процесс (воронка сделки)
1. **Лид** — запрос цены и сроков; прикрепляются Status-файл, табели мер (xlsx), PDF с термотрансфером; указываются модели, размерный ряд, количество.
2. **Расчёт** — расход полотна и фурнитуры, себестоимость, сроки, Gantt.
3. **КП клиенту** — цена FOB, срок, условия. Версионирование КП.
4. **Подтверждение цены и сроков** клиентом (статус + файл/сообщение).
5. **Запуск заказа** — финальный расход полотна и фурнитуры по моделям; заказы поставщикам: **Узтекс** (полотно), **Eren Textile, Турция** (фурнитура).
6. **Образцы** — 1-fit → отправка → подтверждение; предпроизводственные (PP) → отправка → подтверждение. Дата отправки, трек (AWB), дата получения, комментарии клиента.
7. **Производство** — раскрой → пошив → термотрансфер/финишинг/упаковка (полибэг 30×30).
8. **Инспекция AQL 2.5** — финальный отчёт с фото.
9. **Отгрузка в США**.

Правило: запуск закупок и производства блокируется до статусов «Цена подтверждена» и «PP одобрен» (запуск раскроя).

## 4. Функциональные требования
### FR-1 Лид и заказ
- Карточка лида → конвертация в «Экспортный заказ» (клиент, бренд, коллекция, PO, ex-factory, валюта USD, Incoterms FOB).
- Позиции заказа = модели; по каждой: код (SET44.xx), выкройки (GKT/GSH), полотно верх/низ, рибана, отделка, фурнитура, размерный ряд (122–158) с долями, количество (по умолчанию общее на модель).
- **Импорт Status-файла** (xlsx) → автосоздание моделей; импорт табелей мер (листы GKT*, GSH*) в справочник «Выкройки и табели».

### FR-2 Расчёт расхода и стоимости
- Расход полотна по модели/размеру/детали: площадь деталей по табелю × плотность × (1 + отход). Рибана — длина × ширина полосы. Ручная корректировка нормой по раскладке (приоритет над расчётной).
- Сводка по типам полотна → «заказ Узтекс» (кг, метры, +страховой запас).
- Фурнитура по моделям и размерам: шнур, наконечники, резинка 25 мм, бантик, термотрансфер (малый 98–146 / большой 152–182), картонник, полибэг 30×30, короба. Запас %.
- Себестоимость: полотно + фурнитура + CMT + прочее; цена = себестоимость / (1 − маржа); показ маржи в $ и %.
- Версии расчёта и сравнение (было/стало), экспорт в xlsx.

### FR-3 Сроки и Gantt
- Шаблон этапов (23 задачи, см. SPEC): длительности, предшественники, ответственные.
- Автопланирование вперёд от даты старта в рабочих днях; сравнение с целевым Ex-factory; индикатор «опоздание N дней» и критический путь.
- Длительность пошива = количество комплектов / мощность цеха.
- Визуальный Gantt (недели/дни), перетаскивание, фактические даты и % выполнения, уведомления об отставании в Telegram.
- Сценарии «что если» (параллельный пошив, ускоренное полотно, самолётная доставка образцов).

### FR-4 Закупки
- Заказ поставщику (Узтекс/Eren): позиции, объёмы, цена, срок, статус (черновик → отправлен → подтверждён → в производстве → отгружен → получен), файлы (инвойс, пакинг).
- Входной контроль: факт кг/м, усадка, плотность, тон; приход на склад (существующий модуль склада).

### FR-5 Образцы
- Журнал образцов: модель × тип (1-fit, PP) × версия.
- Поля: плановая/фактическая дата готовности, **дата отправки, перевозчик, AWB, дата получения клиентом**, статус подтверждения (ожидает / отправлен / получен / одобрен / одобрен с комментариями / отклонён), дата подтверждения, комментарии, фото образца.
- Напоминания, если клиент не ответил в срок. Портал клиента: кнопки «Одобрить / Комментарий».

### FR-6 Финальный отчёт AQL 2.5
- Автоподбор плана выборки (ISO 2859-1, уровень II): размер партии → код → n → Ac/Re; major AQL 2.5, critical = 0, minor — по требованию клиента.
- Бланк инспекции: проверки (внешний вид, швы, термотрансфер, принт/AOP, шнур/бантик, этикетки, упаковка 30×30, сверка с PP), замеры по табелю мер с допусками (авто-«ВНЕ ДОПУСКА»), список дефектов с категорией, количеством, размером.
- **Фото**: общий вид + каждый дефект (загрузка с телефона через Telegram Mini App, подпись, привязка к дефекту).
- Решение PASS/FAIL по Ac/Re; выгрузка в PDF с фото; хранение в карточке заказа; доступ клиенту.

### FR-7 Отгрузка
- Упаковочный лист по коробам (модель × размер), документы, статус отгрузки и трек.

### FR-8 Уведомления (Telegram) и аудит
- События: подтверждена цена, заказ у поставщика, образец отправлен/одобрен, отставание по Gantt, отчёт AQL готов. Журнал изменений по заказу.

## 5. Нефункциональные требования
Языки RU/UZ (затем EN/TR), валюты UZS + USD, 100+ пользователей, мобильное использование (Mini App), права по ролям, загрузка файлов до 50 МБ, фото сжимаются на клиенте.

## 6. Допущения и риски
- Цены полотна, фурнитуры и CMT — вводятся из котировок; в расчётной модели стоят заглушки.
- Табели мер есть для SET44.01–05; для .06–.11 выкройки приняты по аналогии — подтвердить.
- **Срок:** при последовательном плане (выше) готовность ≈ 8 апр 2027 против целевых 05.01.2027 (запас −93 дня). Для января 2027 нужны: уже готовое полотно/сток, параллельные образцы, подтверждение клиентом по факсимиле/без PP и воздушная доставка — решить с клиентом до КП.
- Количество: в файлах 2 500 шт/модель (+10% = 2 750), в запросе 3 500 — уточнить.

## 7. Критерии приёмки (MVP модуля)
1. Импорт Status-файла создаёт 10 моделей с количеством.
2. Расчёт даёт итог по полотну по типам, совпадающий с excel-моделью ±1%.
3. Gantt показывает расчётную дату и разницу с целевой.
4. Для каждой модели ведётся журнал 1-fit и PP с датой отправки и подтверждением.
5. Отчёт AQL формируется в PDF с фото и корректным Ac/Re.

# Дополнение v2: многопользовательская работа, оповещения по отделам, отдел ВЭД и логистика

## 8. Одновременная работа 8–10+ человек
- Целевая нагрузка: **минимум 10 одновременных пользователей** в одном заказе (рабочий запас — до 30 на фабрику), каждый в своём отделе; в целом 100+ учётных записей (как в textile-crm).
- Одновременное редактирование без потери данных: оптимистичная блокировка (поле `version` у карточек, при конфликте — предупреждение и слияние), блокировка «кто сейчас редактирует» для расчёта и отчёта AQL.
- Живое обновление: статусы, Gantt и комментарии обновляются у всех без перезагрузки (WebSocket/SSE).
- Рабочее пространство по отделам: каждому пользователю видны «Мои задачи», задачи отдела и общая карта заказа; чужие разделы — только чтение.

## 9. Отделы и ответственность за этапы
| Отдел | Этапы / задачи Gantt |
|---|---|
| Продажи | 1, 4, 5 (лид, КП, подтверждение), 10, 17 (отправка образцов) |
| Технологи | 2, 6 (расчёт, раскладки), образцы 9, 16 |
| Закупки | 3, 7, 8, 12–14 (Узтекс, Eren) |
| ОТК | 15, 22 (входной контроль, AQL) |
| Планирование/Производство | 19–21 (раскрой, пошив, упаковка) |
| **ВЭД** | документы и таможня (разд. 10) |
| **Логистика** | бронь транспорта, отгрузка (разд. 11) |
| Директор | дашборд, эскалации |
Каждая задача имеет **отдел-владелец и конкретного исполнителя**, срок (из Gantt), статус, % выполнения и комментарии.

## 10. Отдел ВЭД — документы по экспортной отгрузке
Задачи по заказу создаются автоматически от даты отгрузки (шаблон, сроки редактируются):
| Документ | Источник данных | Когда нужен |
|---|---|---|
| Упаковочный лист (Packing List) | короба × модель × размер, нетто/брутто, кубатура | до загрузки |
| Инвойс (Commercial Invoice) | цена FOB, количество, Incoterms | до загрузки |
| **CMR** | перевозчик, маршрут, груз, места | в день загрузки |
| **ГТД** (экспортная декларация) | коды ТН ВЭД, стоимость, вес | до выпуска груза |
| **СТ-1** (сертификат происхождения) | происхождение товара, инвойс | до отправки в США |
| Прочее (по запросу клиента/таможни) | сертификаты, контракт, спецификация | по необходимости |
Функции: генерация документов из данных заказа (PDF/xlsx по шаблонам), версии, статусы (черновик → на согласовании → подписан → передан), контроль комплекта документов перед отгрузкой (**отгрузку нельзя закрыть без полного комплекта**), хранение файлов, доступ клиенту к инвойсу и упаковочному листу.

## 11. Логистика — бронирование транспорта по кубатуре (м³)
- Расчёт объёма груза: короба × объём короба (габариты, м³) + запас на паллетирование → **объём в м³ и вес** → количество машин (типовой тент 82 м³ — вместимость задаётся в справочнике транспорта).
- Заявка на бронь: дата и время загрузки, перевозчик, тип ТС, маршрут (фабрика → граница/порт → США через мультимодальную схему), стоимость, статус (запрос → подтверждено → машина назначена → загружена → в пути → доставлена).
- Данные машины (госномер, водитель) передаются в ВЭД для CMR.
- Привязка к Gantt (задача 23) и оповещения при риске сорвать бронь.

## 12. Отслеживание и оповещения об опозданиях
- Каждый этап и задача имеет плановый срок; система сравнивает с фактом ежедневно (и при каждом изменении).
- Уровни: **за 1 день до срока** — напоминание исполнителю; **просрочка 1 день** — исполнитель + руководитель отдела; **просрочка ≥3 дня или задача критического пути** — также директор и смежные отделы, чьи задачи блокируются (с расчётом сдвига даты отгрузки).
- Каналы: Telegram (бот Uzexport01_bot, личные сообщения и групповой чат отдела), уведомление внутри CRM; сводка просрочек утром.
- Каждый отдел видит свою ленту: «что мне просрочено / что на подходе / что ждёт меня от других».
- Журнал: кто, когда и что изменил (аудит), причины задержек (справочник причин) — для аналитики.

## 13. Дополнительные критерии приёмки
1. 10 пользователей из разных отделов одновременно работают в одном заказе; правки не теряются, конфликты показываются.
2. При просрочке задачи нужным людям приходит Telegram-сообщение в течение 5 минут.
3. ВЭД формирует Packing List, Invoice, CMR, ГТД, СТ-1 из данных заказа; без комплекта отгрузка не закрывается.
4. Логистика получает объём в м³ и число машин, оформляет бронь со статусами.
