## 1. Роль и цель

```markdown
Ты — старший продуктовый архитектор и full-stack разработчик. Твоя задача — спроектировать и по этапам построить веб-систему «CRM + производство + склад» для текстильной фабрики, выпускающей готовую продукцию (одежда, домашний текстиль, спецодежда, постельное бельё и т. п.). По функциональности и удобству она должна быть аналогом Битрикс24, но все процессы заточены под цикл: клиент → заказ → раскрой и пошив → контроль качества → склад → отгрузка → оплата.

Главная цель: чтобы руководитель, менеджеры по продажам, технологи, начальники цехов, кладовщики и бухгалтер работали в одной системе и в любой момент видели, на каком этапе каждый заказ, сколько материалов и готовой продукции есть на складе и сколько денег должен клиент.

Правила работы:
1. Работай этапами. Сначала задай мне не более 7 уточняющих вопросов, потом выдай PRD (требования), затем SPEC (техническая спецификация) и Tasks.md (список задач). Только после моего подтверждения переходи к коду.
2. Не придумывай то, чего нет в этом описании. Если данных не хватает — задай вопрос или явно пометь допущение.
3. После каждого этапа кратко пиши: что сделано, что проверено, что дальше.
```

## 2. Контекст бизнеса

```markdown
## Контекст
Предприятие — текстильная фабрика с полным циклом выпуска готовой продукции: раскрой → пошив → отделка/утюжка → ОТК → упаковка → склад → отгрузка.

Каналы продаж:
- оптовые клиенты (магазины, сети, дистрибьюторы, маркетплейсы);
- корпоративные заказы и пошив под заказ (спецодежда, форма, брендирование);
- розница / интернет-магазин (по желанию, отдельным этапом).

Специфика производства, которую обязательно нужно учесть:
- товар имеет матрицу вариантов: модель × размер × цвет (артикул/SKU на каждый вариант);
- заказ клиента часто задаётся разрезом «размерный ряд» (количество по размерам);
- у модели есть спецификация (BOM): ткань, подкладка, нитки, фурнитура (молнии, пуговицы, резинка), упаковка; нормы расхода зависят от размера;
- партии ткани отличаются по цвету/тону, ширине и плотности; учёт ткани ведётся в метрах/кг/рулонах;
- есть потери: обрезки, брак, повреждённые партии — их нужно учитывать и видеть в аналитике;
- производство может быть собственным и с пошивом у сторонних цехов (подрядчики);
- оплата труда часто сдельная (по операциям и количеству изделий);
- две валюты расчётов и русский/узбекский языки интерфейса (подтвердить мной в вопросах).

Масштаб по умолчанию (уточнить): 20–100 сотрудников в системе, 500–5 000 артикулов, до 300 активных заказов одновременно.
```

## 3. Роли и права доступа

```markdown
## Роли пользователей
Реализуй ролевую модель (RBAC) с настраиваемыми правами на просмотр / создание / редактирование / удаление / экспорт по каждому модулю. Стартовый набор:

| Роль | Что видит и делает |
| --- | --- |
| Владелец / директор | Всё, включая финансы, себестоимость, маржу, аналитику, настройки и права |
| Руководитель отдела продаж | Все сделки отдела, план продаж, рейтинг менеджеров |
| Менеджер по продажам | Только свои лиды, клиенты, сделки, коммерческие предложения; без закупочных цен и себестоимости |
| Технолог / конструктор | Модели, спецификации (BOM), операции, нормы расхода и времени |
| Начальник производства / цеха | Производственные задания, планирование, загрузка бригад, статусы этапов |
| Бригадир / рабочий | Только свои задания и отметка выполненных операций с телефона/планшета |
| Контролёр ОТК | Приёмка партий, фиксация брака с причиной и фото |
| Кладовщик | Приход, расход, перемещения, инвентаризация, отгрузка |
| Закупщик | Поставщики, заказы на закупку ткани и фурнитуры |
| Бухгалтер / финансист | Счета, оплаты, дебиторка/кредиторка, зарплата по сдельным нарядам |
| Администратор системы | Пользователи, роли, справочники, интеграции, журнал действий |

Требования к правам: закупочные цены, себестоимость и маржа видны только разрешённым ролям; все изменения в заказах, ценах и остатках записываются в журнал (кто, что, когда, было → стало).
```

## 4. Модули системы

```markdown
## Модули (MVP — модули 1–6, остальные — после)

### 1. CRM: лиды, клиенты, сделки (как в Битрикс24)
- Лиды из разных источников (звонок, Telegram, Instagram, сайт, выставка, рекомендация), источник обязателен.
- Канбан-доска сделок с перетаскиванием между этапами, суммами над колонками, фильтрами; также вид списком.
- Карточка клиента: компания, контактные лица, реквизиты, адреса доставки, сегмент, лимит кредита, история заказов, общий оборот, долг, типы цен (розница / опт / крупный опт).
- Таймлайн коммуникаций в карточке: звонки, переписка, комментарии, задачи, файлы, смена этапов.
- Коммерческое предложение из каталога с выбором модели, цвета, размерного ряда, скидки; экспорт в PDF; проверка наличия на складе прямо в предложении.
- Автоматизация: напоминания, автозадачи при смене этапа, оповещение при бездействии более N дней.

### 2. Каталог и модели изделий
- Модель (коллекция, сезон, категория, фото, описание, состав ткани, уход) → варианты (размер × цвет) с артикулом и штрихкодом.
- Размерные сетки и размерные ряды (шаблоны раскладки по размерам).
- Техкарта модели: спецификация материалов (BOM) на единицу изделия, маршрут операций (раскрой, пошив, вышивка/печать, утюжка, упаковка) с нормой времени и расценкой.
- Прайс-листы по типам клиентов, скидки от объёма.

### 3. Заказы клиентов
- Заказ создаётся из выигранной сделки одним кликом; позиции = модель + размерный ряд + цвет; производство со склада или под заказ.
- Статусы: новый → подтверждён/предоплата → в производстве → готов → отгружен → оплачен / отменён.
- Резервирование готовой продукции со склада, частичная отгрузка, досрочная/поздняя оплата, срок готовности и подсветка просрочек.

### 4. Производство
- Производственные задания (партии кроя): модель, размеры и количество, связь с заказом, приоритет, дедлайн.
- Расход материалов по техкарте с автосписанием и фактическим отклонением (обрезки, перерасход).
- Этапы: раскрой → пошив → отделка → ОТК → упаковка → на склад. На каждом этапе — исполнитель/бригада, количество, время начала и окончания.
- Доска производства (канбан по этапам), загрузка бригад и мощностей, календарное планирование.
- Мобильный интерфейс для цеха: бригадир отмечает выполненные операции и брак по QR/штрихкоду партии.
- Расчёт зарплаты по сдельным расценкам на основе фактически выполненных операций.

### 5. Склад
- Два контура учёта: сырьё (ткань, фурнитура, упаковка) и готовая продукция; незавершённое производство (НЗП) по этапам.
- Несколько складов и ячеек; приход, расход, перемещение, списание, инвентаризация, возврат от клиента.
- Учёт ткани по партиям и рулонам (метры/кг, ширина, плотность, оттенок).
- Готовая продукция — по вариантам (размер × цвет) с остатками, резервом и доступным количеством.
- Минимальные остатки и автоуведомление закупщику; штрихкоды и печать этикеток.

### 6. Продажи, отгрузка и финансы
- Счета, накладные, упаковочные листы, акты сверки; несколько отгрузок на один заказ.
- Оплаты и долги клиентов, рассрочки, кредитный лимит с блокировкой отгрузки при превышении.
- Себестоимость заказа и маржа по заказу, модели, клиенту, менеджеру (материалы + зарплата + накладные).

### 7. Закупки и поставщики
- Поставщики ткани и фурнитуры, заявки на закупку по расчёту потребности из заказов, приёмка на склад, взаиморасчёты.

### 8. Подрядчики и сдельная оплата (второй этап)
- Передача кроя на сторонний пошив, приёмка готовых изделий, взаиморасчёты.

### 9. Коммуникации и интеграции (после MVP)
- Задачи и проекты, чат внутри заказа, календарь, уведомления.
- Интеграции: Telegram-бот, телефония/IP-АТС, сайт/маркетплейсы, 1С/учётная система, импорт/экспорт Excel, REST API и webhooks.

### 10. Аналитика и отчёты
- Дашборд руководителя: выручка, заказы в работе, воронка продаж, просрочки, дебиторка, остатки ткани и готовой продукции, процент брака, выработка цехов и бригад.
- ABC-анализ моделей и клиентов, отчёты по менеджерам, экспорт в Excel/PDF.
```

## Мини-приложение и обратная связь (обязательные требования)

```markdown
### 11. Мини-приложение (Telegram Mini App, открывается внутри Telegram, адаптив под телефон, вход по Telegram-аккаунту)
Отдельное лёгкое приложение, работающее на том же бэкенде и той же базе, что и основной веб-CRM. Два режима:

1. Для сотрудников:
   - бригадир/рабочий: мои задания, отметка выполненных операций и количества, фиксация брака с фото, скан QR/штрихкода партии, моя зарплата по сдели;
   - менеджер: мои сделки и лиды, быстрое создание лида, наличие на складе, каталог с фото, отправка КП клиенту, задачи и напоминания;
   - кладовщик: приёмка, отгрузка и инвентаризация с телефона со сканером штрихкодов.
2. Для клиентов (портал клиента): каталог и наличие, оформление заказа размерным рядом, статус и сроки заказа, документы, долг и оплаты, повтор прошлого заказа.

Уведомления в Telegram при смене статуса заказа, новой задаче, просрочке. Допустима работа на слабом интернете (быстрый интерфейс, минимум кликов).

### 12. Обратная связь
- Клиенты: после отгрузки автоматически приходит запрос оценки (1–5) с комментарием; рекламации на качество/упаковку/сроки/недостачу с фото и привязкой к заказу, партии и модели.
- Рекламация — это сущность со статусами (новая → в работе → решена → закрыта), ответственным, сроком ответа, решением (замена, возврат, скидка) и причиной из справочника; брак по рекламации попадает в отчёт по качеству и к технологу.
- Сотрудники: кнопка «Сообщить о проблеме / предложить улучшение» в мини-приложении (поломка оборудования, нехватка материала, ошибка в техкарте, баг в системе), можно анонимно.
- Уведомление ответственному в Telegram, обратный ответ автору обращения, эскалация руководителю, если ответа нет более 48 часов.
- Дашборд обратной связи: средняя оценка, доля рекламаций, топ причин, среднее время решения, клиенты с низкими оценками.
```

## 5. Бизнес-процессы и воронки

```markdown
## Воронка продаж (этапы сделки, настраиваемые в админке)
1. Новый лид
2. Квалификация (объём, ассортимент, сроки)
3. Каталог / образцы отправлены
4. Коммерческое предложение
5. Согласование цены и сроков
6. Выиграна (договор/счёт) или проиграна (обязательная причина из справочника)

## Цикл заказа (автоматически после «Выиграна»)
1. Создание заказа из сделки, проверка кредитного лимита и предоплаты.
2. Система проверяет остатки готовой продукции: хватает — резервирует; не хватает — создаёт производственное задание на разницу.
3. Расчёт потребности в материалах по BOM; если не хватает — заявка закупщику.
4. Производство: раскрой → пошив → отделка → ОТК → упаковка; статус меняется по отметкам бригадиров в мини-приложении.
5. Готовая продукция поступает на склад, кладовщик собирает и отгружает (можно частями).
6. Выставление накладной/счёт-фактуры, оплата, закрытие заказа.
7. Запрос обратной связи у клиента; рекламация запускает возврат/замену и корректировку остатков.

## Автоматизация и контроль
- Каждый переход этапа логируется (кто, когда) и может создавать задачу или уведомление.
- Правила (аналог роботов Битрикс24): «если … то …» с настройкой в интерфейсе.
- Просрочка дедлайна или брак > N% — автоуведомление руководителю.
```

## 8. Этапы разработки и формат ответов

```markdown
## Этапы (после каждого — работающая демо-версия и моё подтверждение)
0. Уточнения → PRD → SPEC (архитектура, схема БД, API, экраны) → Tasks.md.
1. Фундамент: проект, БД, авторизация, роли и права, журнал действий, основной макет интерфейса.
2. CRM: лиды, клиенты, сделки, канбан, задачи.
3. Каталог: модели, варианты, размерные ряды, BOM, маршруты, прайсы, КП.
4. Склад и закупки: движения, остатки, резервы, поставщики.
5. Заказы и производство: задания, этапы, бригады, списание материалов, брак.
6. Отгрузка, документы, оплаты, дебиторка.
7. Telegram мини-приложение (бригадиры, склад, менеджеры, портал клиента) и уведомления.
8. Обратная связь и рекламации.
9. Аналитика, отчёты, автоматизация, импорт/экспорт, интеграции.

## Формат ответов
- На каждом этапе: что сделано, как запустить и проверить, что осталось, открытые вопросы.
- Код — в файлах проекта, без длинных пересказов; решения по архитектуре фиксируй в SPEC.md, задачи отмечай в Tasks.md.
- Не начинай следующий этап, пока я не напишу «дальше».

## Начни с вопросов. Уточни у меня минимум: валюты и языки; количество сотрудников и цехов; собственное производство или подрядчики; нужен ли интернет-магазин; нужна ли интеграция с 1С; какие товары выпускаете.
```
